change: Documentation only, no code behaviour changes. The UI-layer vocabulary is reduced from 4 to 3 and redefined by ROLE: `page` (page.tsx switch + `_screen/<Name>Screen`), `section_container` (= whatever a Screen places directly, in `features/<domain>/components/<Name>`), `part` (everything inside a container; the former `unit_item` and `interaction_parts` are merged). New rules stated in `docs/!must-read/UIレイヤーの概念とコンポーネント分割方法.md` (full rewrite) and CLAUDE.md `ui_layers` / COMPONENTS placement: (1) a Screen imports only `features/<domain>/components/<Name>`, never `<Name>/<Part>` or `common/<X>` (the test:screens check for this lands with the NEXT checkpoint, together with the fixes of the 8 upstream Screens that currently violate it); (2) a container without parts may be a single file `<Name>.tsx` (folder no longer mandatory; with parts: `<Name>/index.tsx` + absolute part imports + barrel, unchanged); (3) `<Section>` is recommended, not mandatory — the kept rule is heading hierarchy (h1 = Screen, h2+ inside) plus a guide for choosing sectioning elements by HTML meaning via `Section as="article|aside|nav"`, never raw tags; (4) container names carry NO suffix (`*Page` / `*Screen` / `*Section` reserved: `*Screen` = page layer, `*Page` = UserPage/AdminPage layout parts only); (5) data seam (must-read §3): first-paint data (balance, first page, record detail, form initial values) is fetched by the loader and passed as an optional `initial<Name>` prop → hook option `fallbackData` with `revalidateOnMount: fallbackData === undefined`; background data (badges, polling, modal contents) stays hook-only; loader calls the same ServerService as the API route. Also updated: `src/lib/screens/README.md` §2/§6, `docs/!must-read/README.md`, `src/components/Layout/README.md`, two code comments.
why: The old 4-layer definition described containers by their markup (`<Section>` top tag, mandatory folder, hook-free "unit items") and the code never matched it (17 of 60 core containers use `<Section>`, roughly half of the 134 parts use hooks, 8 Screens import a part or a `common/` file directly, 6 containers are named `*Page`). Rules nobody follows are either low-value or unenforceable; the rewrite keeps the rules that define the contract boundary (what a Screen may import, top-level props, hooks at the container) and makes them mechanically checkable, and drops form-only rules. The data-seam rule removes the "SSR renders a spinner, client refetches" pattern that was a leftover from pre-loader pages.
