change: Segment 2b, first step (user frame slots). src/app/(user)/layout.tsx and src/app/(user)/(protected)/mypage/layout.tsx are now 1-line switches (`export { UserLayout as default } from "./_layout/UserLayout"`, `export { MyPageLayout as default } from "./_layout/MyPageLayout"`); both are adopter-owned and write-once from now on, like page.tsx. src/app/(user)/_layout/UserLayout.tsx exports the default assembly `UserLayout` with five optional slot props: header, footer, bottomNav (including its spacer), background, notificationModal (omitted = the default part, null = render nothing, an element = render it). The rendered DOM without props is unchanged (ids and order included; fixed by test:user-layout). The header/footer default still comes from src/config/ui/user-header.config.ts / user-footer.config.ts (`UserNavigation` / `UserFooter`), so a fork that switched those to HeaderCustom / FooterCustom keeps its header and footer. The three background values moved from (user)/layout.tsx to the new src/config/ui/user-layout.config.ts (BACKGROUND_IMAGE_URL, BACKGROUND_OVERLAY_COLOR, BACKGROUND_OVERLAY_OPACITY). New src/app/(user)/(protected)/mypage/_layout/MyPageLayout.tsx holds the mypage frame (UserPage narrowStack + Stack + PageTransition). COMPATIBILITY: `UserAppLayout` (old export name and props backgroundImageUrl / overlayColor / overlayOpacity) still works and maps the props to the background slot. The config component re-exports and HeaderCustom / FooterCustom are deprecated (comment and README notices) and are removed in the old-entry removal segment. test:screens now checks frame layouts with the same switch check as page.tsx (src/lib/screens/checks.mjs parseSwitchLayout), and the route map follows a layout switch into its `_layout/` target to pick up guard calls.
why: The council report on shared-folder placement makes every frame layout a 1-line switch owned by the adopter, with the provider's default assembly in `_layout/` taking parts as optional props. A fork then customizes its frame by passing slots (or by a dot-named custom beside the base) instead of editing layout.tsx or switching components in config, which is what made upstream frame changes conflict.
