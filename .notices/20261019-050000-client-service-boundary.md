change: (1) New lint rule `client-service-boundary/no-direct-import` (eslint-rules/client-service-boundary.mjs, test: `pnpm test:client-service-boundary`). It flags UI files that value-import a ClientService: any path containing `services/client` (absolute or relative), or a `*Client` name taken from a domain barrel (`@/features/<d>` / `@/features/core/<d>`). Type-only imports pass. Scope: `src/features/**/components/**` + `src/app/**` (excluding `src/app/api/**` and `src/app/(user)/demo/**`) = warn; `src/components/**`, `src/features/core/**/components/**`, `src/features/_template/**/components/**` = error. (2) Upstream core UI no longer calls ClientServices directly; new hooks: `useSendNotification` (notification), `useReferralsByInviter` (referral), `useAdminWalletHistoryBatches` (walletHistory), `useAuditLogsByTarget` / `useAuditLogsBySubjectUser` / `useAuditLogSearch` (auditLog, new hooks/ dir), `useUserAsyncOptionSource` (user: searchFn + initial-label resolve for user pickers). (3) Parts changed accordingly: `AuditLogListView` now takes `query` (the hook result) instead of `fetcher` / `deps` / `pageSize`, and exports `AUDIT_LOG_OBSERVER_OPTIONS`; `user/components/common/userSelectUtils.ts` is DELETED (pure helpers moved to `@/features/core/user/utils/userOption` — `defaultFormatUserLabel`, `getUserOption`, `mergeUserWhere` (was the private `mergeWhereConditions`), `DEFAULT_USER_SEARCH_FIELDS`; `createUserSearchFn` moved into `useUserAsyncOptionSource`). Public props of `AuditTimeline` / `UserActivityTimeline` / `UserAsyncCombobox` / `UserAsyncMultiSelect` are unchanged. (4) Generator template `Admin__Domain__Sort` now uses `useReorder<Domain>` instead of `<domain>Client.reorder`.
why: CLAUDE.md requires HTTP to go Hook → ClientService, but nothing enforced it, and upstream core itself had 13 direct calls from components. Without a hook in between, the same fetch is re-written per screen and SWR caching / mutation concurrency safety (useDomainMutation) are bypassed.
required_actions:
1. Merge upstream. If your fork imports `@/features/core/user/components/common/userSelectUtils` (or the `@/features/user/...` short form), tsc fails: switch to `@/features/core/user/utils/userOption` for the pure helpers, and to `useUserAsyncOptionSource` instead of `createUserSearchFn`.
2. If your fork copied or calls `AuditLogListView` directly (it is a part, not contract): call one of the new auditLog hooks in the caller and pass its result as `query`, with `observerOptions: AUDIT_LOG_OBSERVER_OPTIONS` (tsc points at the call sites).
3. Regenerate business domains that have a sort screen: `pnpm dc:generate -- <Domain>` (or `pnpm dc:generate:all`) so `Admin<Domain>Sort` picks up the hook. Generated files only; no fork-owned file changes.
4. Run `pnpm eslint src`. Errors from this rule can only appear in core paths (src/components, features/core, _template) — i.e. files the fork edited at core paths; fix them the same way (wrap in a hook). Warnings in your own UI (features/<business>/components, app/ screens) are the backlog: wrap each direct call in a hook under that domain's `hooks/` (derived `useInfiniteScrollQuery` for lists, `useDomainMutation` for writes, `useSWR` for reads). A genuinely legitimate exception gets `// eslint-disable-next-line client-service-boundary/no-direct-import` with the reason above it. Fixing all warnings is NOT required to close this checkpoint.
