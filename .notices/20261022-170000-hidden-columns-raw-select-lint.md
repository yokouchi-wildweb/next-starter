change: SECURITY. New ESLint rule `hidden-columns/no-raw-select` (eslint-rules/hidden-columns.mjs, registered in eslint.config.mjs as **error** for src/**, excluding services/server/finders/ and entities/) flags raw drizzle queries that pull hidden columns (defineHiddenColumns, e.g. users.localPassword, paired device token hashes) out of the DB: explicit `<Table>.<hidden>` or `getTableColumns(<Table>)` inside select / returning, and full-row `select().from(<Table>)` / `insert|update|delete(<Table>)…returning()` on tables that declare hidden columns. New helper `getPublicColumns(<Table>)` (@/lib/crud/drizzle/hiddenColumns) returns the table's columns with hidden ones replaced by `null as "<column>"`. Upstream fixed its own 20 hits (user creation paths, pairedDevice, fingerprintChallenge); POST /api/admin/user/demo/create and POST /api/setting/setup no longer return the password hash.
why: hiddenColumns only strips createCrudService results and relation embeds; raw drizzle rows bypass it, and rows handed to HTTP responses or Client Components (RSC payload) leak the hash. Found in the admin user list loader of an oripa-do lineage replacement screen (custom sort queries selecting localPassword).
