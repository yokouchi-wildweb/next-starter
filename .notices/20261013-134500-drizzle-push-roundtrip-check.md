why: drizzle-kit 0.31.x cannot read back indexes written as `sql\`${col} DESC\`` or mixing plain columns with SQL expressions, so `db:push` DROPs and re-CREATEs them on EVERY push even when the DB already matches — silently (no --verbose) and with a write lock on large production tables (pandora play_batches 1.2M rows). Default drift (array/jsonb) had the same root-cause family. The check makes "push twice = zero diff" verifiable so non-round-trippable schema is caught in dev, not production.
required_actions:
1. `pnpm install` (applies the drizzle-kit patch; lockfile gains a patchedDependencies entry — commit it).
2. `pnpm db:push` on the dev DB, then `pnpm db:push:check`. Expected: zero statements. If DROP INDEX + CREATE INDEX pairs remain, rewrite those index definitions per scripts/registry/README.md: `sql\`${t.col} DESC\`` → `t.col.desc()` (or `.desc().nullsFirst()` when adopting an existing physical index created as plain `DESC`, which is NULLS FIRST), mixed column+expression index → every column as `sql\`${t.col}\``. Re-run until zero. Do NOT change `where` only (push does not detect where-only changes; handle manually).
