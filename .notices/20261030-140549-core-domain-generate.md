change: (1) The generator (dc:generate, dc:generate:all, forge, dc:feature-map, dc:delete) now treats `src/features/core/<domain>/domain.json` like a business domain; only the folder differs. One place resolves where a domain lives (scripts/domain-config/domain/workspace.mjs locateDomain); the same name in both places stops. Differences for core: the generated imports stay `@/features/<domain>/...`, so tsconfig.json `paths` needs `"@/features/<domain>/*": ["./src/features/core/<domain>/*"]` (missing → stops before writing and prints the line); nothing is appended to src/registry/ (schemaRegistry, domainConfigRegistry and adminDataMenu come from `pnpm registry:generate`, storage purposes stay hand-written in src/features/core/storageObject/purposes/, a line says so); domainEntry.ts is written, so serviceRegistry.ts lists it as it does for hand-written core entries. The 13 upstream core domain.json files get `"generate": false` (nothing else changes). src/features/feature-map.txt core rows now show domain.json yes / no and the flag. Relations to a core domain now read its domain.json too: a generated drizzleBase.ts whose belongsTo / countable relation points at core `user` (useSoftDelete: true) gets `useSoftDelete: true, deletedAtColumn: UserTable.deletedAt` in that relation, so after regenerating, relation counts no longer include soft-deleted users and an embedded user (creator etc.) can come back empty when that user is soft-deleted (council decision L1.32). (2) A domain with `"generate": false` never goes through the generator: in every run (dc:generate:all, forge, dc:generate <Domain>, `--only`, `-i`) it writes nothing and runs no checks; it prints one line `generate: false（手で管理）のため何も書きません`. Before, `--only` wrote the named categories even for generate: false domains, and their checks could stop a whole `dc:generate:all` (e.g. a misspelt mediaTypePreset in a hand-managed domain).
why: New core domains and rebuilding lightly extended core domains need the same generator (council decision D41); hand-managed domains must never be touched by a generator run (the human's decision during this order).
