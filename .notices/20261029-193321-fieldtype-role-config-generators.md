change: The profile generators of role-config (`scripts/role-config/generator/generateProfileSchema.mjs`, `generateProfileDrizzle.mjs`, `generateProfileModel.mjs`, `generateProfilePresenters.mjs`) now read the fieldType table (`src/lib/domain/fields/fieldTypes.mjs`: zodType, tsType, column / columnMode, text / email / enum / array / datetime attributes) and `presenterFor`, instead of their own type switches. The table gains two attributes used here: `emailFormat` (email) and `enumValues` (enum), with helpers `isEmailFieldType` / `isEnumFieldType`. Profile-specific rules stay: datetime Zod is always `nullableDatetime`, boolean columns are notNull + default(false) unless `nullable`, timestamptz columns get no default, types without a column function become `text` columns, media / collection fields get no presenter. Rule changes: a profile field with fieldType `jsonb` is now generated as a `jsonb` column (was `text`); `array` / `stringArray` become `text[]` columns with `[]` default (was jsonb / text); `numeric(10,2)` columns get `{ mode: "number" }`. userProfile/README.md's extraWhere example now uses `arrayContains` on a text[] column.
why: role-config was a third copy of the type rules and had drifted (council S7). Generated profile files stay the same for every profile field in the forks surveyed except fieldType `jsonb` (one field in two forks).
