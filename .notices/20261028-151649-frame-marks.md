change: Segment 3, step 1 (frame controls become marks). (1) HideHeader / HideHeaderNav / HideFooter / HideBottomNav (src/components/AppFrames/User/controls/, names, props, exports and paths unchanged) are no longer client components: no "use client", no hook, no context. Each renders an empty mark `<span hidden data-frame-hide="<part>-<device>">` (part = header | header-nav | footer | bottom-nav, device = sp | pc). (2) New generated stylesheet src/styles/frame-controls.generated.css (imported by global.css after config.css, unlayered) hides a part with `display: none` while the outer frame `[data-frame-root]` contains its mark (CSS `:has()`, media `(width < 40rem)` / `(width >= 40rem)` = Tailwind sm). Targets = the default parts' ids (header, header-pc-nav, header-sp-menu-toggle, header-sp-nav, footer, bottom-nav, bottom-nav-spacer-sp, bottom-nav-spacer-pc) and `[data-frame-part~="<part>"]`. (3) Single source: src/components/AppFrames/User/controls/frameParts.ts; `pnpm frame:generate` writes the CSS, `--check` and `pnpm test:frame-controls` fail on drift. The CSS declares a marker variable `--frame-controls-generated`, so `pnpm build`'s styles:check-build fails if the file is missing from the build output. (4) UserLayout's #user-app-container gets `data-frame-root`; the default Header, the header nav parts (PC nav, SP menu toggle, SP menu), Footer, BottomNav and both BottomNavSpacer divs get `data-frame-part`. Without a Hide* the rendered DOM is unchanged except these attributes. (5) Semantics: hide only and additive (any mark hides); `sp={false}` / `pc={false}` now do nothing (they used to mean "show on that device"). Marks work from server and client components and take effect the moment they are inside the frame (no wait for hydration). A mark drawn in the outer frame itself works from the SSR HTML alone; a page's mark under (user)/loading.tsx (a Suspense boundary) takes effect when the streamed page content arrives: while loading, the parts show; they hide in the same frame the content appears (no flash with JavaScript enabled). With JavaScript disabled the streamed content never enters the frame, so page marks do not apply (the page content does not show either). The visibility contexts stay but Hide* no longer writes to them (their values stay at the defaults).
why: The council report on shared-folder placement replaces the client-side visibility control with a server-renderable mark plus one CSS `:has()` rule per part: no client JS (CSS rules only), parts hidden the moment the page content appears instead of after hydration, usable anywhere, and no cleanup race between leaving and entering pages (a mark disappears with its page).
