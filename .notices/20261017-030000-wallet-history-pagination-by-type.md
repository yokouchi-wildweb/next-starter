change: Bug fix in the per-currency wallet history screen (`/wallet/<slug>/history`). (1) `listBatchSummaries` (walletHistory server service) gains an optional `walletType` param and filters in SQL (`WHERE user_id = ? AND type = ?`, uses the existing `wallet_histories_user_type_created_idx`). (2) `GET /api/wallet/history/batches` accepts an optional `type` query param (validated with `isWalletType`, invalid value → 400; omitted = all currencies as before). (3) `walletHistoryBatchClient.list` query type gains `type?: WalletType`. (4) NEW hook `useMyWalletHistoryBatches({ walletType, limit?, enabled?, observerOptions? })` in `src/features/core/walletHistory/hooks/` (built on `useInfiniteScrollQuery`, returns its result as-is; fetch is disabled while `walletType` is null/undefined). (5) `WalletHistoryPage` (section container) now uses that hook and no longer calls the client service directly nor filters by currency on the client. All additions are backward compatible; `AdminWalletAdjustModal/HistoryTabContent` (admin, all currencies) is unchanged.
why: `WalletHistoryPage` fetched page 1 of ALL currencies, filtered to the target currency on the client and returned `total: filtered.length`. `useInfiniteScrollQuery` stops when `items.length >= total`, so the list always ended after the first page: with mixed currencies, more than 20 batches, or a target currency absent from the first 20 batches, the user saw a truncated list or "履歴はまだありません" although history exists. The fix moves the currency filter to SQL so page size and `total` describe the same set. Also removes a client-service direct call from a section container (CLAUDE.md: HTTP via ClientService, components go through hooks) ahead of the Step 5 screen work.
