change: New read-only command `pnpm dc:compare [<Domain>...] [--base <ref>] [--detail] [--json <file>]` helps a fork decide `generate` true / false per domain. For every business domain it compares each file the generator manages three ways: the current file / the output of the generator at the fork's last upstream merge (merge-base with the `upstream` remote, or `--base`) / the output of today's generator, and sorts them: 未改変 (same as the base output; "上流の改良で変わる" when today's output differs), 手の変更の見込み (lines inserted into the base output), 古い生成物の見込み (lines only deleted or replaced: output of an older generator kept as is), 新しく作られる (with admin pages / _screen / domainEntry.ts listed as 新しい入口), 残る (write-once files the generator keeps), fork files the generator never makes (wrappers/ counted apart), 表の定義の書き直し (entities/drizzle.ts would change). Each domain gets a verdict: true にできる / 確かめて true / wrappers へ移すか false / 直してから (today's generator stops; the reason is printed). It reads domain.json files that still have `generateFiles` (it rewrites only copies in a temp directory) and writes nothing in the repo (only `--json` writes the file you name). `--detail` lists every file with its line counts and the subject of the commit that last touched it. dc:parity now builds its old side with the same code, and its old side also takes the ref's templates (src/features/_template, src/app/admin/_template; before, the working tree's templates were used on both sides, so template changes never showed up); those folders are not compared.
why: A mechanical migration makes most domains of a large fork hand-managed and cuts them off from generator improvements; the fork should decide each domain on evidence of its own hand changes (council decision D42).
