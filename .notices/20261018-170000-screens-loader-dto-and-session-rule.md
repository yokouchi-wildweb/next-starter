change: Three SCREENS loader rules added to src/lib/screens/README.md §3/§4 and enforced by `checkLoaderFile` (src/lib/screens/checks.mjs, run by `pnpm test:screens`). (1) DTO ownership: the loader DEFINES and exports its types `<Name>ScreenData` (return) and `<Name>ScreenParams` / `<Name>ScreenSearchParams` (input); the Screen and its parts `import type` them from the loader (`./loader` / `../_screen/loader`). A loader must not import anything (value or type) from `_components/` or from a `*Screen` file — the checker FAILS on such an import source (relative imports are resolved from the loader's own path, so `./Part` from a `_components/loader.ts` counts too). (2) Session helper by route group: a loader under a `(protected)` path segment (`(user)/(protected)`, `admin/(protected)`) that needs the user uses `requireCurrentUser({ behavior: "redirect", redirectTo })` with the same `redirectTo` literal as that group's layout `authGuard` (`/login`, `/admin/login`). `getSessionUser()` is for public routes with optional personalization only; the checker FAILS when a loader under `(protected)` imports `getSessionUser`. Ownership / existence hiding (someone else's record → 404) stays a `notFound()` after the user is obtained. (3) Naming (documented, not checked): public `load<Name>Screen(props)`, cache()'d inner `resolve<Name>Screen(primitives)`; a loader without arguments may wrap `load<Name>Screen` itself in `cache()`.
why: oripa-do (upstream-request 20261018-163744) migrated 9 routes and found both gaps: a loader whose return type was declared in a client part under `_components/` (the contract's type dictated by a non-contract file, so a fork replacing the part changes the loader's "contract"), and protected loaders split between "getSessionUser → render defaults when null" and "requireCurrentUser → redirect". Under `(protected)` the layout has already redirected, so the null branch is dead code and the two styles only add a per-loader decision. Fixing the route group once removes that decision; owning the types in the loader keeps the contract's shape in the contract file.
