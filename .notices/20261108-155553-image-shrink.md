change: Automatic image shrinking on upload, declared once per storage purpose: StoragePurpose.image = { maxDimension, quality? } (hand-written purposes in src/features/core/storageObject/purposes/) or "storage": { "image": { ... } } on a domain.json media field (generated purposes). With it, MediaUploader / MediaUploaderMulti / FieldRenderer media fields shrink the image in the browser before the size check (shrinkImageForPurpose), and the server redraw (stripImageMetadata) shrinks it again to the same limit. New public functions in @/lib/storage/client: shrinkImageFile(file, spec), shrinkImageForPurpose(file, purpose); MediaInput / MediaUploader / MediaUploaderMulti take an optional prepareFile(file) => Promise<File> that runs before the size check (the purpose's shrink runs after it). Without a declaration nothing changes.
why: Phone camera originals exceed typical purpose limits and were rejected before anything could shrink them; a fork had to edit MediaInput (FORK_EXTENSION judge 3). Shrinking is now a declaration; forks remove their own shrinking code and its permit.
