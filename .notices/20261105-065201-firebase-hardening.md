change: (1) Firebase ID token verification now checks revocation: verifyIdToken(idToken, true) in firebaseSession / registration / preRegistration / verifyPhoneOtp; a revoked token or a disabled Firebase user gets the existing 401 "認証情報の検証に失敗しました". (2) Client `fstore` (src/lib/firebase/client/app.ts) is no longer initialized while NEXT_PUBLIC_FIREBASE_* is empty: touching it throws FirebaseNotConfiguredError("client"), like `auth`. (3) Firestore rules: upstream ships a deny-all template firestore.rules.example and a chatRoom example src/features/core/chatRoom/firestore.rules.example; firestore.rules / firestore.indexes.json are removed from .gitignore (forks commit their own); firebase.json is now an intake point (`edit firebase.json`) so a fork may add its "firestore" block. (4) createDirectRoom adds where("participants", "array-contains", myUid) to its existing-room query (same results; needed for participant-only rules).
why: Firestore rules are the only guard for what the browser reads and writes directly (chatRoom). The old setup doc sample let every signed-in user read and write every document. A revoked Firebase token could still be exchanged for a new app session until it expired.
