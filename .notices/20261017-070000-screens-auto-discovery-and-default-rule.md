Supersedes notice 20261017-050000 (registry entries + `owner`): (1) `screens.test.mjs` now auto-discovers every `page.tsx` under `src/app/(user)/**` and `src/app/(marketing)/**` (except `(user)/demo/**` and `_`-prefixed dirs) plus dc:generate admin routes (derived from `src/features/*/domain.json`, `generateFiles.adminRoutes !== false`), and every `src/features/**/services/server/loaders/*.ts`. `UPSTREAM_ROUTES`, `FORK_SCREEN_ROUTES`, `ScreenRouteEntry`, `owner`, `isRouteOwner`, `UPSTREAM_OWNER`, `registerRouteTests` are REMOVED. (2) Per discovered page.tsx: it must be a 1-line switch to `./_screen/<X>` OR `./_components/<X>` (default + `metadata` / `generateMetadata` / `viewport` / `generateViewport` re-export allowed; segment config like `dynamic` stays in page.tsx) — otherwise the test FAILS unless the route is listed with a reason in a legacy list: upstream's `UPSTREAM_LEGACY_ROUTES` (in `screens.test.mjs`, 38 core routes still to migrate in steps 5b–5e, shrinks each step) or the fork's `FORK_LEGACY_ROUTES` in `src/registry/screenRoutesRegistry.ts` (`LegacyRouteEntry { dir, reason }`, upstream ships empty, downstream-owned). A listed route whose page.tsx has become a switch to `./_screen/` also FAILS ("remove from the list"); a switch to `./_components/` (= replaced by a downstream of the list's owner) does NOT count as migrated, and a listed route that no longer exists is only reported for `FORK_LEGACY_ROUTES` (the fork can edit it), never for upstream's list. (3) The referenced Screen is resolved as `<X>.tsx` → `<X>/index.tsx` → one barrel level (StarterHome-style directories work), must named-export the default-bound name, must NOT `export default`, and must NOT carry `"use client"` (Screens are Server Components; hooks go to section containers). (4) `stripComments` rewritten as a one-pass scanner: a `//` comment containing `/**` (e.g. `// see /api/me/**`) no longer swallows the following `import "server-only"`. (5) Pure checkers moved to `src/lib/screens/checks.mjs` (`parseSwitchPage`, `checkSwitchPage`, `checkScreenFile`, `checkLoaderFile`, `stripComments`); `checkLoaderFile` accepts any `load<Xxx>` export (shared admin loaders). (6) CLAUDE.md SCREENS `downstream` line now says DEFAULT RULE; README rewritten (§7 "自分のページを作る（原則この構造）", §9 auto-discovery, §10 legacy lists, §11 why registration was dropped).
why: Three forks (TriQ, oripa-do, boardgame-site) asked for registration points and checker fixes within hours of the pilot (upstream-requests 20261017-142638, 20261017-144504, and 20261017-141216 already shipped as 050000). The registration design shipped in 050000 was wrong for this upstream's top priority (nothing to remember, no daily chores): every new page needed a registry line, a forgotten line silently skipped the check, and "recommended" produced no migration pressure — forks kept legacy routes unless told explicitly. Auto-discovery removes the chore entirely, and the legacy list turns "silently old" into "explicitly deferred with a reason", which is the intended level of enforcement (default rule with explicit exceptions, not absolute).
