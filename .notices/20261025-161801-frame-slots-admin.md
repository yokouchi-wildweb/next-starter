(3) AdminProtectedLayout and InsaneProtectedLayout take optional `sidebar` (the content inside the PC column and SP drawer shells; default = the current sidebar; null = no sidebar, resize handle or SP toggle) and `footer` (default = the current footer for (protected), none for insane; null = none). (4) AdminPage takes `tabs` (rendered above the children with a bottom margin, also with fill). (5) BREAKING DEFAULT: the admin PageTitle default is now placement="header" (on sm and up the title is drawn in the header's title receptacle and hidden in the page body; below sm it stays in the body). Upstream's admin login and setup screens now pass placement="page". (6) test:screens detects frame switches only by a re-export from ./_layout/ (a guard layout.tsx importing its ./_layout frame is not a switch). (7) Old-path references left inside upstream admin files (layout imports, the adminLayout store import, file header comments) now use the new paths. The rendered DOM without the new props is unchanged except for (5).
why: The council report on shared-folder placement makes the admin frame the same shape as the user frame: an adopter-owned 1-line switch with the provider's default assembly taking parts as props, while guard layouts stay provider-owned. Admin screens nearly all show their title in the header, so the default follows the common case; header receptacles become a tested contract so a replaced header does not silently drop titles and portal content.
