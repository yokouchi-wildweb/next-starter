change: domain.json `generateFiles` (per-category booleans) is removed and replaced by one flag `generate` (boolean, omitted = true). true = `dc:generate` regenerates every category of that domain (a collection child: entities / serverServices / registry / fieldConstants / presenters only, decided by the generator); false = the domain is hand-managed and the generator writes nothing for it (no registry append, no domainEntry.ts rewrite, no child domain.json). A domain.json that still has `generateFiles` STOPS `dc:generate` before anything is written ("generateFiles は廃止しました"). `--only <categories>` still narrows one run. The interactive "manual selection" is no longer saved to domain.json. The required-key check of notice 20261029-203513-domain-strict-checks for the 9 generateFiles keys is gone (its step "add the missing presenters key" is no longer needed). New collection children are written without generateFiles. Generated domainEntry.ts / collections.ts header comments change (comment lines only).
why: Per-category switches let a domain half-follow the generator, so a regeneration silently overwrote hand-edited files in categories left on. One flag per domain makes the choice explicit: either the generator owns the domain (hand logic lives in wrappers/ and the write-once service) or the fork owns it.

2. For each one: if every value in its generateFiles is true, delete the `generateFiles` block. Collection children written by the generator (their generateFiles had components / hooks / clientServices / adminRoutes false only) just delete the block (the generator decides their categories). Core domain.json files are config sources only: deleting their block is optional.
3. Regenerate the domains left with generate true: `pnpm dc:generate:all --yes`, then `pnpm typecheck`.
