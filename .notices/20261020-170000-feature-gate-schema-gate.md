change: Feature Gate now closes a disabled feature on both routes and tables. (1) Gate rules moved from src/proxies/featureGate.ts (FEATURE_GATE_RULES, `isEnabled: () => boolean`) to src/config/app/feature-gate.config.ts (`featureGateRules`, `{ pathPatterns, tables?, enabled: boolean, redirectTo? }`); featureGate.ts keeps only matching + response, export name featureGateProxy unchanged. (2) New flag APP_FEATURES.payment.enabled (default true) for purchase / payment webhook / bank transfer / purchase quota; isPaymentMethodSelectable() returns false when it is off. (3) wallet / payment / coupon rules now cover every route of those domains (pages, /api/me/*, generic /api/<domain>, admin analytics incl. coin-issuance, webhook, cron). (4) Schema gate: `pnpm db:push` is now scripts/registry/push.ts (drizzle-kit/api pushSchema, not the drizzle-kit CLI) and, with db:push:check, removes the `tables` of disabled rules from both the code side and the DB side of the diff: a disabled feature's tables are never created and never dropped (enabling it later creates them on the next push; enums are always kept). (5) Callers outside the gated domains now check the flags: userCleanupRegistry handlers, registration invite-code redemption (also needs coupon), coinIssuanceRegistry sources, admin user list wallet adjust, cron task enabled() of wallet-* and expire-pending-purchases. (6) New test `pnpm test:feature-gate`. Also: role-config scripts and READMEs now say `pnpm db:push` instead of `drizzle-kit push`.
why: with only wallet.enabled=false a fork still exposed /api/webhook/payment, /api/me/wallet, coupon-issuer APIs, purchase/wallet analytics and wallet crons, and db:push created every payment table, so "keep upstream code unused" was not safe. Forks that edited FEATURE_GATE_RULES in core featureGate.ts will conflict, and raw `drizzle-kit push` no longer applies the gate.
