change: SCREENS loaders now live INSIDE the route, next to the Screen: `src/app/<route>/_screen/loader.ts` (fixed file name, 1 route = 0..1 loader, same owner as `_screen/`). The rule "loader goes to `features/<domain>/services/server/loaders/`" is withdrawn for per-route loaders; `features/` keeps ONLY shared loaders used by many routes (the dc:generate admin loaders in `features/core/admin/services/server/loaders/`). Upstream moved its 3 wallet loaders to `src/app/(user)/(protected)/wallet/{,[slug]/,[slug]/history/}_screen/loader.ts`; the old files `src/features/core/wallet/services/server/loaders/{walletIndex,walletBalance,walletHistory}.ts` are now re-export shims (same exports, same behavior) and WILL BE DELETED after this checkpoint. Also: (1) `ScreenProps<P>` accepts optional catch-all params (`{ status?: string[] }`). (2) README wording: a loader calls `requireCurrentUser` when it reads user-scoped data (not "every protected page"); a page with no server-side fetch has no loader at all (no guard-only loaders). (3) A navigation-only loader may return `Promise<void>`. (4) Per-domain `loaders/README.md` lists are no longer required; the loader's header comment is its spec (shared-loader dirs keep their README). (5) `cache()` stays REQUIRED even for pure param-parsing / redirect-only loaders (uniform rule, no opt-out marker). (6) `_components/` keeps its dual role (page-only parts + downstream replacement Screens); name replacement Screens `<Name>Screen.tsx` to tell them apart — no third directory name. (7) `pnpm test:screens` now checks each discovered route's `_screen/loader.ts` and `_components/loader.ts`, skips re-export-only files under `features/**/loaders/` (`isReexportOnlyFile` in checks.mjs), and `parseSwitchPage` allows page.tsx (generateMetadata) to import `./_screen/loader` / `./_components/loader`.
why: oripa-do (upstream-request 20261018-150616) migrated 20 routes and hit the gap: pages that compose several core domains (user + userProfile etc.) have no domain to own their loader, and core is upstream-owned, so the fork had to invent an entity-less pseudo-domain (`features/mypage/`). Redirect-only and param-parsing loaders had the same problem. Putting every per-route loader inside its route removes the placement decision entirely (nothing to remember), keeps 1 route = 1 Screen = 0..1 loader visible in one directory, and lets a deleted route take its loader with it. The wallet move is done now while it is one day old and cheap.
