change: API routes are now built from configured Factories in src/wiring/apiRoute.ts (import from "@/wiring/apiRoute"; src/lib/routeFactory is the generic version, value-importable only from src/wiring/**). The Factory resolves the DB-synced user once per request and passes ctx.user for every access; access is "public" | "authenticated" | { roles?, roleCategories? } (+ allowStatuses on every Factory) — "custom", ctx.session (token-only) and requireRole.ts (requireAdmin / requireAuthenticated) are removed. All upstream routes were rewritten to declared access + ctx.user. New lint rules, all tiers error: route-http-export/http-export (every GET…OPTIONS in src/app/**/route.ts = a call of a wiring / @/lib/cron Factory), import-boundaries/route-factory-via-wiring, import-boundaries/lib-no-registry (src/lib → src/registry forbidden, values and types; upstream-owned shrinking exception list only), page-authz/session-api-callsite now covers src/app/api/** (no session / requireRole / token-only session / jwt cookie parsing in routes or their helper files). route-authz/require-authz and AUTH_SIGNALS are removed. Responses: a returned plain Response is passed through; DomainError gains optional code / details (put in the body); 401/403 bodies carry code ("unauthenticated" / "forbidden") and generic CRUD adds { domain, operation }; 404 stays text/plain. Fork wiring files: src/wiring/<name>[.client].<fork-id>.ts(x) with `fork_id:` declared in .claude/rules/project.md.
why: Authorization is wired in one place and principal resolution is structural (no per-route session reads, no token-only role checks). Fork routes using the removed APIs stop at `pnpm typecheck` and `pnpm lint` from this checkpoint on; there is no transition period.
