Without the new props every existing output is unchanged (outputs recorded before the change are compared in tests). (1) AsyncComboboxInput and AsyncMultiSelectInput: renderOption: AsyncOptionRenderer<T> = (option, item) => ReactNode (same shape as AsyncPickerModal's; the type is exported from Form/Input/Manual/AsyncOptionSource) draws candidate rows, the single input's pinned selected row and the multi input's selected rows; item = the fetched row from the engine cache (undefined when only an initial label is known); the trigger label / chips stay the label. (2) AsyncComboboxInput: scopes ([{ value, label, count? }] = tabs under the search box, count shown as 「(n)」; scope / defaultScope / onScopeChange) and allOption ({ value, label } = a row always at the top; picking it calls onChange(allOption.value); the trigger shows its label for that value; the value is the caller's, distinct from null = cleared). searchFn now receives a second argument { scope }; changing the scope reloads page 1 of the current mode (browse or search). Types AsyncComboboxScope / AsyncComboboxAllOption / AsyncComboboxSearchContext. (3) StateTabs: variant ("segment" default = today's look | "underline" = bottom border, primary text and underline on the active tab, same as PageTab's UnderlineTabs; explicit appearance class props still win) and listEnd (ReactNode at the right end of the tab row; the list shrinks). Type StateTabsVariant. (4) AppImage: style and data-* attributes (type AppImageDataAttributes) on the outermost element (fill = the box div, intrinsic = the img); data-component="AppImage" stays the part's; other attributes are still not forwarded. (5) Span: inline (boolean) = display inline, size / weight default to inherit, line-height follows the parent; explicit size / weight / tone still apply. (6) EditProfile: afterSaveHref accepts null = after a successful save it stays (no push), shows a success toast 「プロフィールを保存しました」 and refreshes; backHref then defaults to "/mypage/account". (7) AccountAvatarSection (core user part): renderFallback(user, size) is removed and children is taken instead (shown inside the size × size circle when no avatar is set; default = the person icon). (8) Rules: .claude/rules/core/components.md `slots` and src/components/README.md = slots by owner (src/components and libs: look props and content slots allowed; core domain parts: value props and children only; core default containers and screens: no named slot, recompose from exported parts and hooks, a receptacle for what upstream screens mount); .claude/rules/core/extensions.md own_mark = an optional line-1 mark `// instead-of: <upstream entry> ; why: lacks <what>|looks|business ; order: <order id>|-` on a file a fork built instead of an upstream part, and /flux step 6 lists these marks whose entry changed (with copied-from).
why: Forks no longer need their own comboboxes to show badges per row, scope tabs or an "all" option, their own tab rows for a side button or underline tabs, next/image directly for a data-slot or a style, raw spans inside text, or a whole EditProfile copy to stay on the page after saving. The rule texts say which slots each kind of part may take and give forks a way to note what they built instead of an upstream part. Replacing existing code is optional.
