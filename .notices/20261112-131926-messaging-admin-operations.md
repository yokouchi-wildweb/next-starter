change: Admins can cancel, retract and resend a dispatch. New admin API POST /api/admin/messaging/dispatches/[id]/cancel (only a scheduled dispatch not yet expanded → cancelled), /retract (deletes the dispatch's inbox rows — the shared row for all / role sends and per-recipient rows —, cancels unsent deliveries and pending retries, stops the expansion and sets retracted_at; the dispatch status is unchanged; mails already sent cannot be recalled; final, no undo; inbox images are detached like the retention sweep) and /resend { includeUnknown? } (failed deliveries of a non-required dispatch: messages that keep their body (record vars / full) are requeued on the same dispatch with the same idempotency key; record meta messages are sent as a new dispatch from the dispatch's input copy (metadata.resendOf); unknown deliveries only when includeUnknown is true, and the dispatch records possibleDuplicate; secret-carrying and required messages are refused). Refusals are 409 with a reason code; the codes and texts live in src/features/core/messaging/constants/dispatchOperations.ts (DISPATCH_OPERATION_REASONS / DISPATCH_OPERATION_REASON_TEXT). GET /dispatches/[id] returns operations { cancel, retract, resend: { allowed, reason, mode, failed, unknown } } and the dispatch detail screen shows 予約を取り消す / 取り下げる / 失敗分を再送 with confirm dialogs, disabled with the reason when not allowed. Audit actions: messaging.dispatch.cancelled, messaging.dispatch.retracted, messaging.dispatch.resent. The routes sit under /api/admin/messaging/dispatches, so the gate messagingDispatches covers them.
why: A wrong or failed admin send had no way back: no cancel for a schedule, no way to pull an inbox notice, no resend of failed deliveries.
required_actions:
1. Nothing is required. The buttons appear on /admin/messaging/[id] wherever the dispatch screens are open (gate messagingDispatches, default open).
2. A fork that shows its own dispatch screen reads the operations flags of the detail and the reason texts from @/features/core/messaging/constants (DISPATCH_OPERATION_REASON_TEXT), never the 409 body (the route factory's error body may not carry the code).
3. Tell admins that retract only removes inbox notices and stops unsent deliveries: mails already delivered stay with the users, and a retract cannot be undone.
