change: `pnpm test:screens` now scans fork-declared areas. `src/registry/screenRoutesRegistry.ts` (downstream-owned, upstream ships empty) gained `FORK_SCAN_ROOTS: string[]` (repo-relative dirs under src/app, ONE LINE PER AREA, e.g. "src/app/store", "src/app/terminal", "src/app/admin/(protected)/floor-tables") and `FORK_SCAN_EXCLUDES: string[]` (same prefix semantics as upstream SCAN_EXCLUDES). `discoverPages()` walks `[...SCAN_ROOTS, ...FORK_SCAN_ROOTS]` minus `[...SCAN_EXCLUDES, ...FORK_SCAN_EXCLUDES]`; pages found under fork roots get exactly the same tests as upstream routes (switch / Screen / `_screen|_components/loader.ts`) and honour FORK_LEGACY_ROUTES. Two new tests: (a) freshness — a FORK_SCAN_ROOTS / FORK_SCAN_EXCLUDES entry that is not an existing directory, is duplicated, or is malformed (not `src/app/...`, trailing slash) → FAIL; a FORK_SCAN_ROOTS entry already covered by SCAN_ROOTS / a dc:generate admin dir / another fork root, or one that CONTAINS an upstream area (`src/app/admin`, `src/app/admin/(protected)` — register your own sub-dir instead), or one inside an exclude → FAIL; (b) unregistered area — a directory directly under `src/app` that contains a page.tsx and is neither inside a scan root (or has a scan root inside it), nor inside an upstream known area (`admin`, `debug`, `api`), nor inside an exclude → FAIL with the line to add (route-handler-only dirs like `sitemap.xml/` and dot-dirs are ignored). Known limit: (b) only looks at top-level dirs; a fork sub-dir inside an upstream area (`src/app/admin/(protected)/floor-tables`) is NOT auto-detected and must be registered. The test imports the registry as a namespace and treats a missing export as empty, so a bad merge of the registry file fails the freshness test instead of crashing the suite.
why: TriQ (upstream-request 20261018-164509): notice 20261017-070000 asked forks to delete their local screen tests, but SCAN_ROOTS was fixed to (user)/(marketing), so a fork's own top-level areas (store console, kiosk/terminal, hand-written admin tools) were never discovered and deleting the local test would silently drop their coverage; TriQ kept ~100 lines of duplicated test code. Fork-declared roots keep the 070000 principle (nothing to remember per page — one line per AREA) without pulling upstream's 37 hand-written admin/debug pages into the legacy list, and the unregistered-area test turns "forgot to register" from silent into loud.
