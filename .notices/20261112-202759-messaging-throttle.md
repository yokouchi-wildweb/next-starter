change: Messaging throttle (D48) now takes effect. A definition / override `throttle: { by, mode, seconds }` is applied per recipient before the channel sends, on both the in-request send and the cron send. Throttle key = sha256(recipient key × message_key × by values). untilRead (inApp in the dispatch channels): an unread per-user inbox item with the same key is replaced (latest content, collapsed_count + 1, the earlier dispatch appended to collapsed_dispatch_ids, dispatch_id → the new dispatch, published_at → now, stays unread); the inApp delivery is sent + reason throttled, other channels are suppressed + reason throttled (channel_counts.skipped_throttled). window (and untilRead without inApp): a previous send with the key within seconds → the same (inApp: replace the unread item, or a new item when it was read). First send / after the window / after read send normally. {{collapsedCount}} is filled (1 normally, the count on a replaced item). The decision runs once per (dispatch, recipient) inside a transaction holding pg_advisory_xact_lock on the key, so overlapping request and cron sends never double. For throttled messages the inApp item is written by the throttle step (shape from channels/inApp inAppItemRow), not by the inApp channel send. Shared all / role dispatches are never throttled. New columns: message_inbox_items.throttle_key / collapsed_count (default 1) / collapsed_dispatch_ids, message_deliveries.throttle_key, with two indexes. sweep aggregateDeliveries rows carry reason.
why: The new columns must exist before this code runs (every send path reads / writes throttle_key). No upstream definition declares throttle, so upstream behaviour is unchanged until a fork adds one.
