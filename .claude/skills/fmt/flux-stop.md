# flux-stop
when: /flux が止まって人の返事を待つとき(初回の承認・区間の終わり・停止条件で止まったとき)と最終報告
not: all / light で止まらずに進むときの短い途中報告 | /flux と無関係の判断(→ ask)

reader_goal: 読み手がこの文章だけで、いまどこに居て、次に何が起きて、何と答えればよいかを決められる

## 構造
位置          | 必須 | 区間 k/N と状態(承認待ち / 停止 / 終了)。初回は規模(上流のコミット数・notice 件数・区間数)と、普通でないこと(未コミットの変更、履歴が辿れない等)
区間の結果    | 任意 | 終えた区間。取り込み・適用・検査が問題なく済み push したか、1 行。人の方針で残したもの・こちらの誤りなど例外があるときだけ行を足す
中継          | 任意 | 下流を持つ fork は毎回。あり = 下流が何をすべきか・なぜ。なし = 一言の理由
止まった理由  | 任意 | 停止条件のとき。見つけたこと・根拠・選べる道
次の区間      | 任意 | 承認の対象(最終報告には無い)。下の 6 点で書く
  変わる点         | 必須 | 取り込みで fork に起きる変化。箇条書き、短く
  体験の変化       | 任意 | 使う人の画面・挙動が変わるときだけ、具体的に
  fork の追従      | 必須 | あり / なし を明示。あり = 何を(役割で)・どれだけ(本数・箇所数)・どんな作業か・どこに影響しうるか
  db:push          | 必須 | あり / なし を明示。あり = 何が作られる・変わるか
  ダウンタイム     | 必須 | 要る / 要らない を明示。要る = どの操作の間か
  手動のデータ移行 | 任意 | DB・Storage などで手で動かすものがあるときだけ
  逸脱             | 任意 | 定型の手順から外れる手当て(人の方針が要る衝突の解き方、追加の検査など)
残りの概観    | 任意 | 番号 + 日本語の要旨 + 判断に効く注記(「区間 13 で修正される」「移植あり」)。前回から変わらなければ 1 行
宿題          | 任意 | notice の manual_steps。人がやることのチェックリスト
上流への所見  | 任意 | 区間の終わりでは**この区間で新しく見つけたもの**だけ + 累計件数(「新規 1 件、累計 3 件」)。新規が無ければ累計だけ 1 行、累計も 0 なら書かない。最終報告では全件
問い          | 必須 | 返事の語彙を添える。最終報告では終了の宣言と残りの区間

## 契約
- 返事の語彙: 初回の承認 = go / go last / いいえ | 区間の終わり = go / go last / 再計画 / ここで終える
- 作業メモ: チャットに出さないものは flux の作業メモに書く(台本 = 適用手順・衝突予測・検査項目 / 判定根拠 = 中継の基準・除外した件数 / aligned・kept_old / 再開用 = 区間ごとの sha・次の merge 先・人が下した判断 / 番号 ↔ checkpoint ラベル ↔ sha の対応 / 上流への所見の全件と根拠)。置き場と寿命は flux の SKILL.md が決める。聞かれたらここから答える
- fork の追従の「どんな作業か」の語彙: 置き換え(呼び方・置き場所を揃えるだけ)/ 作り直し(fork の実装を新しい仕組みに乗せ換える。動作確認が要る)/ 判断が要る(上流と fork の意図がぶつかり、人が決める箇所がある)

## 指針
- ファイル・コミット・notice は名前ではなく役割で呼ぶ。識別子は作業メモへ
- 確認して「なし」だったものは書かない(あり / なし の明示が必須の 3 点だけ例外)
- 定型の手順(merge → 検査 → 台帳 → commit → push)は書かない。書くのは逸脱だけ
- 内部の記号(info / breaking、判定基準の番号、軽い / 重い)を出さない。重さは 6 点から読み手が判断する
- 経緯ではなく現在地。再開に要る情報は作業メモが持つ
- 検査の結果は「問題なし」で足りる。失敗は停止条件で止まるので、ここに失敗は来ない

## 例
```
区間 1/18 完了 → 2/18 承認待ち
区間 1: 取り込み・適用・検査すべて問題なし、push 済み。
  中継: あり — fork が既定を変えた画面スイッチの設定が上流の変更と重なるため、下流も自分の値を見直す必要がある。中継 notice 作成・push 済み
  こちらの誤り: 中継 notice と台帳の時刻を実時刻より 1 時間後に書いた(順序の表記だけの実害。出荷済みなので残す)

次の区間 2/18: notice に「どの依頼を解決したか」の欄を足す変更
変わる点
- notice に解決した依頼を書く欄が増え、所有の検査がそれを読んで一時許可の期限切れを判定する
- /ship・/flux の手順書が新しい欄に対応する(次の区間から新しい手順で進む)
fork の追従: なし(fork の独自コードは上流の変更に触れていない)
db:push: なし
ダウンタイム: 要らない

残り: 区間 3〜18 は前回から変わりなし

次の区間 2/18 をこの計画で進めますか?(go / go last / 再計画 / ここで終える)
```
