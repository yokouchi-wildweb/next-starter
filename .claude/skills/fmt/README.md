# 書式ファイルの書き方

書式 = 「こう書けば伝わりやすい」という知識。各書式ファイルは単体で完結させる(共通部品を参照しない。同じ内容が複数の書式に要るなら、それぞれに書く)。

## ファイルの形

```
# <書式名>
when: いつ使うか(状況を名指し)
not: 似ているが使わない状況(→ 代わりの書式)
reader_goal: 読み手がこの文章だけで何をできればよいか。1 文。これが唯一の合否基準

## 構造
節を順に並べる。1 節 1 行: <節名> | 必須|任意 | 種類 | 役割(読み手のどの疑問に答える節か)
種類 = 結論 | 差分 | 本文(下の「節の種類」)

## 書かないもの
書きがちだが読み手の役に立たないもの。1 行 = <書かないもの> — <理由>。構造の節と同じ重みで読まれるように、必ず置く

## 契約(任意)
他の仕組みが依存していて変えられないもの(返事の語彙、節の名前など)。無ければ節ごと書かない

## 指針
数行。目的を言う形で書く

## 例(任意)
短い実例 1 つ。構造が伝わる最小のもの
```

## 書くときの約束

- 時間の向きで分量を決める: 読み手の注意は、これから起きること・決めることに使う。通り過ぎたこと(済んだこと、前に見せたこと)は結論だけ
- 節の種類(分量を数値ではなく役割で決める目安。書き方までは縛らない):
  - 結論: 一言の判定。問題がなければそれで終わる。例外があるときだけ、その例外を書く
  - 差分: 前回の文章から変わったことだけ。変わっていなければ「変わりなし」の一言
  - 本文: 読み手が判断に要るだけ詳しく
- 書式は型ではなく目安: 構造・種類・書かないものの範囲で、言い回しや並べ方はその場で決める
- 節は役割で定義する。分量・粒度・文体の数値制約(「3 行以内」など)は置かない。分量は役割と reader_goal から、使う側がその場で導く
- 構造にない節は、状況が求めるときに足してよい(名前は役割が分かる言葉で)。契約の節だけは増減・形の変更をしない
- 例は品質を上げるが、型にはめる力も強い。自由度を残したい書式は例を薄く、他の仕組みが読む書式は例を付ける
- 短くさせたい節(結論・差分)だけは、悪い例と良い例の対を 1 組付けてよい(長く書く方へ流れる力に対抗するため)
- when / not は対で書く。使うかの判断は「使わない場面」で揺れる
