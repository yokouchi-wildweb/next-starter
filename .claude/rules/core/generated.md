# generated
> **ROLE**: loaded when touching generated files or their sources | holds DIRECTORY_STRUCTURE code_generation (generated / write-once / hand-owned)
> Tier1-owned: forks never edit (gap → /order next-starter)

code_generation:
- output kinds = data: scripts/structure/domain/phase.json outputs[] { glob, kind, source } (kind every-run | write-once, source = what to edit instead; test: scripts/structure/domain/tests/outputs.test.mjs keeps it equal to the generator's writes) | per path: pnpm workflow ownership who \<path\> (type generated / own / none, write = the source)
- generated (kind every-run; no edit; overwritten on every forge / pnpm generate domain while the domain's `generate` is true): e.g. entities/, components/Admin*/, hooks/use*\<Domain\>.ts, services/server/drizzleBase.ts, app/admin/(protected)/\<domains\>/**/_screen/ (full list = the data)
- registry: pnpm generate domain writes, in each domain it generates (domain.json with generate not false), only that domain folder: services/server/domainEntry.ts (from apiAccess / useImportExport), collections.ts, storagePurposes.ts, every run; at the end it regenerates serviceRegistry (and district-map.jsonl), no other registry
- display: \<domain\>/entities/display.ts = client copy of domain.json (allowlisted keys only, no secrets), generated by pnpm generate registry | client parts, _template and generated Fields read it, never domain.json (key list: src/lib/domain/README.md) | a domain without domain.json hand-writes the same shape
- registries: serviceRegistry, schemaRegistry, domainConfigRegistry, storagePurposeRegistry, adminDomains = generated whole by pnpm generate registry (never edit; no fork region)
  - forge runs it; after a lone pnpm generate domain / pnpm generate domain -- --delete run pnpm generate registry for the other registries (serviceRegistry is already rewritten; pnpm check registry stops until then) | admin menu rows → receptacles src/domains/core/admin/menu/ (README there)
  - a domain with generate false or no domain.json (every core domain today, not the definition of core): domainEntry.ts and the rest are hand-written | a domain leaves the admin data menu by addToAdminDataMenu false in domain.json | extension points → scripts/structure/extensions/README.md
- fork_region: in the `region` files of src/lib/forkOwnership/intake.txt (room registry; src/registry has none; seeds are per-domain seed.ts with no registry) a fork writes only between `// --- fork entries start (upstream never edits inside) ---` and `// --- fork entries end ---` (imports included; several pairs per file OK) | outside the pairs = upstream's
  - generator blocks (AUTO-GENERATED*) are not fork regions | guarded by src/lib/forkOwnership/regions.test.mjs, the old marker strings fail (/sluice runs it) | ref: src/lib/forkOwnership/README.md
- write-once (kind write-once; generated when absent, never overwritten, then the owner's hand file): e.g. app/admin/(protected)/\<domains\>/**/page.tsx (1-line switch), services/server/\<domain\>Service.ts (compose base + wrappers here), \<domain\>/seed.ts (defineSeed data, ref: src/lib/seed/README.md; not for Firestore)
- hand-owned (not in the data, never overwritten): files you add under wrappers/, formEntities.ts, any other file you add (other constants/ files, hooks with non-generated names), app/admin/(protected)/\<domains\>/**/_components/
- role / profile: pnpm generate role (forge runs it) writes user/extensions/roles.ts, userProfile/extensions/profile{Bases,Configs,Schemas,Tables}.ts (declared writer "role:generate") and userProfile/entities/profiles/\<name\>/ | no edit
  - fork changes values only in \<json name\>.override.ts beside the JSON (added roles: label, hasProfile, enabled; core roles in coreRoles/: label, hasProfile; profiles: tags, searchFields, audit), upstream ships none | ref: src/domains/core/userProfile/README.md
- form inputs: pnpm generate extensions writes src/wiring/formSuite.ts (list + knot FormInputsRoot) from \<domain or lib\>/plugs/formInputs/\<name\>.ts | unknown formInput (not builtin, not registered) stops generation of generate:true domains and profiles | ref: src/lib/formSuite/README.md Extension
- `generate` (domain.json, default true; a per-category generateFiles key is not supported and stops generation) | true = all categories rewritten every run (collection children: the generator picks their categories)
  - must hand-edit a generated file or re-applying hand logic gets costly → `"generate": false` = the generator never touches that domain (no writes and no checks in any run, `--only` / `-i` included; regenerate once = set it back to true)
  - after switching a domain to false: `pnpm generate domain -- --unmark <Domain>` removes the generated marks from its files (a mark left on a hand-managed file makes pnpm check rules fail)
  - src/registry/district-map.jsonl lists every domain with domainJson and its generate flag (rewritten by pnpm generate district-map and at the end of pnpm generate domain, `pnpm check district-map`) | ref: scripts/structure/domain/README.md
- vercel_json: its crons key is generated (pnpm generate cron, kept other keys and rows) but the file is 5 self, not a generated output (no intake.txt generated row): each deploying repo commits its own | → core/design.md self_files
- district_map_tools_only: src/registry/district-map.jsonl is for tools (people, agents, /sluice and /flux diffs), never imported from src (lint import-boundaries/src-no-district-map)
