# docs/journal/ — 日付付きの記録

その時点で何が起き、何を確かめ、なぜそう決めたかを日付付きで残す場所です。コードや README は「今どうなっているか」しか表せないため、経緯はここに置きます。自動ロードされないので、分量を気にせず書けます。

## 置くもの

- インシデントの経緯（原因調査の過程、切り分け、最終的な原因）
- 検証結果（実機確認、Playwright での確認内容、件数の前後比較）
- 決定の経緯（検討した選択肢、見送った理由、方針が変わったきっかけ）
- 段階的な作業のログ（各ステップで何をしたか）
- 「記録して」「残しておいて」の受け皿

## ファイル名と所有者

`<YYYY-MM-DD>--<owner>--<slug>.md`（例: `2026-10-18--next-starter--ui-layers-revision.md`）

- owner = その記録を書いた repo の名前（origin URL の最後の部分を小文字にしたもの）
- 本文の冒頭に `> owner: <repo名>` の 1 行を書く
- 1 件 1 ファイル。追記で育てず、新しい出来事は新しいファイルにする

上流の記録は merge でこのフォルダに届きます。owner が自分の repo でない記録は、その repo の経緯として読んでください（自分の repo の判断根拠にはしない）。

## ほかの文書との分担

ここに書くのは、ほかの文書に置けない「経緯」だけです。次のものはそれぞれの場所に書きます。

- 恒常ルール・判断基準 → `.claude/rules/project.md`（1 行に蒸留する。経緯の本文はここに残し、`ref: docs/journal/<file>` で参照する）
- 機能の仕様・使い方 → コード隣の README.md
- upstream の core 部品に関する教訓 → `/order <上流リポ>` で上流へ
