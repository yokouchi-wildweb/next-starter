# 3 つの法則

> **この文書が裏付ける CLAUDE.md の節**: 冒頭の法則（`ai_native`・`domain_driven`・`debt_free` と `use` の行。最初の見出し `THIS_FILE` より前）
> **正本は `CLAUDE.md` 冒頭の英語の法則**。この文書はその人向けの訳と説明で、法則の文を変えることはない。ずれたら正本が正しく、この文書を直す。法則の文を変えるときは、変える前にボスの承認を取る(Tier1 のどのセッション・議会でも。フォークからは next-starter へ依頼を出し、受けた Tier1 が承認を取って直す)。

## 1. 訳

`CLAUDE.md` の 1〜14 行を、行ごとに訳す（`|` は項目の区切り、`→` は「だから」）。

### 第 1 法則 ai_native（エージェントの開発に最も向いた形を取る）

1. **ai_native**: エージェントによる開発が最も効率よくなる環境とアーキテクチャを常に選ぶ ｜ 前提: このコードを書くのは人の手ではなくエージェントで、エージェントはこのフレームワークがそろえ続ける網羅的な文脈（コンテキスト）と道具一式の上に立っている → コード全体を読むことも大きく書き換えることも、速く・正確で・安い
2. **エージェントを強くする道具**: エージェントの作業を速く正確にするために、道具を積極的に作って使う ｜ 道具はエージェントに仕えるもので、エージェントがしてよいことを縛らない
3. **覚えておくより書くか検査する**: 次のエージェントは今日の会話を何も知らない → 守られるべきことは文脈（決まり・札・README）か検査に入れる

### 第 2 法則 domain_driven（業務のドメインを設計の単位にする）

4. **domain_driven**: 業務のドメインが設計の単位: 1 つの業務の概念が要るものは、ほかのどのドメインとも同じ形で、そのドメインの中にまとまる → 仕様の変更は 1 か所にとどまり、機能の門番（feature gate）がドメインをまとめて開け閉めするので、機能はまるごと足され・閉じられ・取り除かれる
5. **共有の置き場より持ち主のドメイン**: コードはその概念を持つドメインに置く ｜ どのドメインにも属さない物だけが lib（仕組み）か共有の部品（UI）になる ｜ 1 つのドメインだけが使う部品はそのドメインに置く
6. **手を伸ばすより渡す**: lib はドメインを import しない（要る物は渡してもらう） ｜ ドメインがほかのドメインに届くのは、その公開のフックとサービスを通してだけ
7. **中央の一覧より各ドメイン自身の分**: 機能・アクセス・テーブルはドメインごとに宣言する ｜ 機能 = プロジェクトが入れたり切ったりする単位で、その規則が開くドメインを挙げる
8. （7 の続き）ドメインは自分のスイッチを持たない: 開いている機能のどれかに挙げられている間は開き、開いている機能のどれにも挙げられていなければ、そのページ・API・テーブル・定期の作業がまとめて閉じる → 新しい仕組みは、各ドメインが自分の分を持つ形で作る

### 第 3 法則 debt_free（負債を残さない）

9. **debt_free**: 実装の判断はどれも、長い目で見て最も筋がよくきれいな形を目指し、今たどり着ける中でそれに最も近い状態を作る ｜ 先の負債より今の作業を選ぶ
10. **当て布より根本**: 原因を残したままの応急処置・回避策・特例を置かない ｜ 手間を省くために古い物を新しい物の横に残さない（別名、途中までの移行）
11. **負債を抱えるより今払う**: 次のどれも、案を不利にする理由に数えない: コードの書き換えの量（呼び手を全部書き換える、改名、移動） ｜ テストと文書の書き直し ｜ データの移行（列やテーブルの作り直し、今ある行の移動） ｜ 運用の一時の負担（保守の時間、1 回きりの移行作業）
12. （11 の続き）これは案を選ぶときの話で、誰が手順を走らせるかの話ではない: 手順を走らせるのは決まりが名指す人のまま

### 使い方 use

13. **use**: 以下の決まりはすべてこの 3 つの法則から出てくる ｜ どの決まりにも無い問い → 法則で決める ｜ 設計やリファクタリングの開いた選択 → 法則が勧める案を取る ｜ 法則どうしが食い違う → 前の法則が先（ai_native、次に domain_driven、次に debt_free）
14. （13 の続き）書かれた決まりは法則より強い: 法則を破るように見える決まりにも従い、無視しない。その上で直すために `/order`（その決まりの持ち主への依頼。`CLAUDE.md` REPO_LINK）を出す

## 2. それぞれの法則が何を言い、なぜそうするか

### ai_native: 文脈と道具が支える

このコードは人の手ではなくエージェントが書く。だから「人が読み書きしやすいか」ではなく「エージェントが速く正確に作業できるか」で環境と構成を選ぶ。エージェントにとって、全体を読むことや大きく書き換えることは安い。ただしそれが成り立つのは、決まり・札・README という網羅的な文脈と、生成・検査・スキルという道具がそろっているからで、そろえ続けることもこのフレームワークの仕事に入る。

- **エージェントを強くする道具**: 道具はエージェントの作業を速く正確にするためにある。繰り返す作業や間違えやすい作業は道具に持たせ、足りなければ作る。ただし道具はエージェントを縛らない: 決まりが道具に割り当てた一歩(push は /sluice、生成物はその生成器、repo.json はその命令)のほかは、合う道具を使い、無ければ直に作業して、結果を検査に任せる。道具が止めてよいのは本番・push・人の決定の前だけ
- **覚えておくより書くか検査する**: エージェントは会話をまたいで覚えていない。今日わかった守るべきことは、次のエージェントが読む場所（決まり・札・README）に書くか、破ったら止まる検査にする

### domain_driven: ドメインをまとめて開け閉めする

1 つの業務の概念（ユーザー、ウォレット、クーポン…）に要るものを、そのドメインの中に、どのドメインとも同じ形でまとめる。そうすると仕様の変更はそのドメインの中で閉じ、ドメインを足すときも消すときもそのフォルダを見れば済む。

このフレームワーク特有の仕組みが **機能の門番（featureGate）**。機能 = プロジェクトが入切する単位で、その規則が開くドメインを挙げる。ドメインは自分のスイッチを持たず、開いている機能に挙げられていれば開き、どれにも挙げられていなければページ・API・テーブル・定期の作業がまとめて閉じる。中央の一覧で 1 つずつ止めるのではなく、各ドメインが自分の分（機能・アクセス・テーブル）を宣言しているから、まとめて開け閉めできる。仕組みの詳細は `CLAUDE.md` DOMAINS_AND_FEATURES と `src/featureGate/README.md`。

- **持ち主のドメインに置く**: 「とりあえず共有の場所へ」を許すと、どの概念の物か分からないコードが増える。どのドメインにも属さない物だけが lib か共有の部品になる。置き場所の詳しい判断は [設計思想とアーキテクチャ](設計思想とアーキテクチャ.md)
- **渡すか、公開の口から届く**: lib がドメインを読むと、lib を直すたびにどのドメインが壊れるか追えなくなる。ドメインどうしも公開のフックとサービスだけでつながる

### debt_free: 書き換えの量を不利に数えない

判断のたびに、長い目で見て最も筋のよい形を目指し、今できる中でそれに最も近い状態を作る。ここで大事なのは「書き換えが多いから」「テストを直すのが大変だから」「データの移行が要るから」を、案を退ける理由にしないこと。エージェントにとって書き換えは安い（第 1 法則）ので、手間を理由に負債を残すほうが高くつく。

- **根本を直す**: 原因を残す応急処置や特例は、次の変更のたびに同じ問題を呼ぶ
- **古い物を残さない**: 別名や途中までの移行を残すと、やり方が 2 つになり（第 1 法則に反する）、どちらが正か読み手が迷う。呼び手を全部書き換えて、古い物は消す
- **選ぶ話と走らせる話は別**: 「移行作業の負担を数えない」は案を選ぶときの話。DB への反映や本番の作業を誰が走らせるかは、決まり（`repo.json` の agent の方針など）が名指すとおり

## 3. 決まりとぶつかって見えるときの扱い

- **書かれた決まりが先**: 法則を破るように見える決まりでも、その決まりに従う。法則を理由に決まりを無視しない
- **直すのは依頼で**: ぶつかっていると思ったら、その決まりの持ち主へ `/order` で依頼する（決まりの文書 = CLAUDE.md・core・Tier1 の札なら next-starter へ直接。`CLAUDE.md` REPO_LINK）。待つ間の扱いは `CLAUDE.md` REPO_LINK の contract_gap
- **決まりに無い問い**: 法則で決める。開いた選択では法則が勧める案を取る
- **法則どうしの食い違い**: 前の法則が先（ai_native → domain_driven → debt_free）
